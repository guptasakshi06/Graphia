## What and why

This checkpoint verifies the application that students will demonstrate. A
passing function test alone cannot show that the upload widget, image displays,
OCR-source choice and download buttons all connect correctly. We used the real
browser, encoded fictional images and local Tesseract, then inspected actual
browser downloads. No production implementation change was necessary.

## How the existing functions connect

- `collect_uploads` snapshots file bytes and creates index/hash IDs. Two files
  named alike must remain two records. Unique document types still count once.
- `load_real_provider` selects Sakshi's real loader, pipeline and OCR. There is
  no fixture switch in the production app.
- `analyze_uploads` runs both OCR paths and uses the chosen text for both
  classification and extraction. Its separate views hold image arrays; reports
  retain only serializable text, fields/settings and error information.
- `run_pipeline` supplies original, grayscale, denoised, enhanced, thresholded and
  morphology images. Grayscale keeps brightness without color; filtering reduces
  small noise, CLAHE changes local contrast, and thresholding separates light and
  dark pixels. Otsu chooses one threshold from the image; adaptive uses local
  neighbourhoods (block 31, C 11 here). Morphology was bypassed throughout this
  browser validation. Defaults were not changed or claimed optimal.
- `input_signature` and `invalidate_results` keep reports tied to their exact
  input/settings/checklist/source. After a change, wait for Streamlit's rerender
  to remove old results, then explicitly analyze again.
- `analyze_readiness` separates presence from usable information. Three usable
  types of four = `100 × 3 / 4 = 75%`. A recognized Identity Proof with no required
  name raises coverage to 100%, while readiness stays 75%. An unrelated page,
  blank image or corrupt bytes cannot satisfy a type. Readable is a heuristic;
  a readable file with missing required fields is still unusable.
- `render_report` converts the same structured report to readable Markdown. We
  compared the actual downloaded Markdown to this renderer of its JSON pair.
