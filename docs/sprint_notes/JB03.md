## What and why

After OCR, classification supplies a document type and extraction supplies fields.
This sprint compares that information with a configurable, fictional scholarship
checklist. It is ordinary Python application logic downstream of DIP/OCR; it does
not modify images or run Tesseract. No additional dependency is needed.

`config/requirements.json` is the contract-v1 demonstration policy. All four
types need `student_name`. Income/caste certificates additionally need
`certificate_number`. `application_id` and `issue_date` are optional initially.
These are sample requirements, not official scholarship rules.

## How the checks work

1. `analyze_readiness(records, config, required_types=None)` validates inputs.
   None selects all configured types. A nonempty subset changes the denominator.
2. It reads each record's selected `ocr` result. `ocr_source` must identify the
   same result in `ocr_original` or `ocr_processed`. The caller must classify and
   extract from this selected text too; readiness does not rerun those functions.
3. Readable means status `ok` **and** at least `min_alnum_chars` characters for
   which Python `str.isalnum()` returns True. The default is 20. Spaces and
   punctuation do not count; Unicode letters/digits do. Confidence does not
   change the decision. A status of `error` or `no_text` cannot be readable.
4. A known-type candidate is usable when readable and every required field for
   its type is a nonempty string after stripping whitespace. No fields are
   borrowed from another record. Unknown records cannot be usable candidates.
5. Sets hold detected and usable required types. Uploads remain separate records
   even with identical filenames. Duplicates cannot inflate unique-type totals.

Coverage = `100 * detected_required_type_count / required_type_count`.
Readiness = `100 * usable_required_type_count / required_type_count`.

For four required types, three detected/usable types gives 75% for both.
Four detected and three usable gives 100% coverage and 75% readiness. With three
required types and one usable, the stored value is `100 / 3`; Markdown displays
33.33%. Calculations keep their original precision.

Status priority is `Incomplete` when any type is absent, then `Needs Attention`
when all types are present but some have no usable candidate, otherwise `Ready`.
A recognized unreadable document is present and unusable, not missing.

## Key functions and validation

- `_validate_config` rejects missing/extra configuration keys, blank profile names,
  empty required-type mappings, unknown types/fields, duplicate fields and invalid
  thresholds (including booleans/floats). Selection must be nonempty, unique and
  limited to configured types. A per-type empty field list is allowed explicitly
  to require only readability; the supplied default uses the required baseline.
- `_validate_ocr` checks the OCR result shape and preserves error/no-text states.
  `_copy_record` requires unique stable IDs and the contracted record keys, checks
  source consistency and string/None fields, and copies only public report data.
  Missing/malformed caller data raises `ValueError`; it never becomes fabricated
  successful OCR. Nonserializable data/NaN inside report fields is rejected.
- `analyze_readiness` copies data and adds checks without mutating caller records
  or configuration. Unknown/unselected files remain in the report but cannot
  increase selected checklist counts. A known unselected file's `usable` flag
  describes its own configured requirements; `is_required` says whether it counts.
- `render_report(report)` returns Markdown with configuration, counts, percentages,
  missing/unusable types, files, evidence, fields, problems, selected text, settings
  and limitations. It does not write files. Missing values display as
  `Not Found / Unreadable`. Inline data is escaped and raw OCR uses a code fence
  longer than any backtick run it contains.

## Report schema for JB04

The result includes every required contract-v1 key: `profile_name`,
`required_types`, `required_type_count`, `submitted_file_count`,
`detected_required_type_count`, `usable_required_type_count`, `missing_types`,
`unusable_types`, `coverage_percent`, `readiness_percent`, `overall_status`,
`documents`, `limitations`. It additionally includes `configuration`, a copy of
the complete validated policy; `required_types` records the effective selection.

Each document preserves `id`, `filename`, `ocr_original`, `ocr_processed`,
`ocr_source`, `ocr`, `classification`, `fields`, `processing_parameters`. Added
keys: `doc_type`, `is_required`, `alnum_char_count`, `readable`, `required_fields`,
`missing_required_fields`, `usable`, `problems`. Raw OCR and engine configuration
are retained in JSON. Image arrays stay outside exports. Serialize using
`json.dumps(report, ensure_ascii=False, indent=2, allow_nan=False)`.
