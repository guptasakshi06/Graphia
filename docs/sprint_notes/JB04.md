## What the UI does and why

The story is upload bytes → explicit Analyze → contracted image/DIP/OCR calls →
selected OCR text → type and fields → configured readiness → screen/downloads.
In this checkout the real image/OCR imports are absent. That boundary gives a
clear error and no report; tests separately inject visibly fictional data.
There is no API server, database, account, external service or deployment.

Upload multiple JPG/JPEG/PNG files, choose a nonempty checklist, choose processing
options, then Analyze. Each file keeps its own ID even when two files share a
name or identical bytes. Results show six named stages, both OCR texts/statuses,
keyword evidence, extracted values, readable/usable flags, missing and unusable
types, distinct file/type counts, coverage/readiness and downloads. Missing
fields display `Not Found / Unreadable`; their JSON values remain null.

For example, four selected types with only one usable detected type give 25%
coverage and readiness, even when two uploads contain the same good type. The
fixture UI tests use this case plus a corrupt third file. These numbers are
known-text rule/UI checks, not measured OCR results.

## Important functions in app.py

- `collect_uploads`: uses each upload's `getvalue()` bytes. ID combines upload
  position and SHA-256 of filename/bytes. Duplicate records cannot overwrite one
  another. IDs are stable for unchanged input order; reordering/changing inputs
  invalidates the old batch.
- `input_signature` / `invalidate_results`: hash upload IDs, all pipeline
  settings, selected required types, OCR source and full configuration. On any
  change, remove the whole analysis (report and display arrays). Downloads appear
  only when that analysis exists. Analyze also clears results before retrying,
  so an import/setup failure cannot leave an old Ready report visible.
- `load_real_provider`: delayed imports of `modules.preprocessing.load_image`,
  `modules.preprocessing.run_pipeline`, `modules.ocr.extract_text`. There is no
  test-mode switch in the running app. Missing imports produce the explicit
  `Awaiting real DIP/OCR modules` message. No peer code was copied here.
- `analyze_uploads`: calls `load_image(bytes, max_dimension=1800)`,
  `run_pipeline(image, options=...)`, and `extract_text(image, lang="eng", psm=6,
  timeout=20)` for original and processed images. Contract-v1 records contain all
  nine canonical keys. Separate `views` hold image arrays, never JSON reports.
  Processing parameters retain requested options, max dimension, loaded width
  and height, and the pipeline's resolved settings. The loader owns resizing,
  EXIF/alpha normalization and image validity for actual processing.
- `call_ocr` / `error_ocr`: preserve explicit failures. An OCR exception becomes
  status `error`, never a successful empty string. A corrupt image still gets a
  record. Original OCR runs independently before the pipeline, allowing original
  selection even if processing fails. A successful engine's `no_text` remains
  distinct from an error. Unexpected malformed provider contracts fail visibly
  at the analysis boundary rather than fabricating results.
- `display_pixels`: flips BGR channels only for display (`[:, :, ::-1]`); a gray
  image is already two-dimensional. A BGR pixel [0, 0, 255] becomes RGB [255, 0,
  0], red. Display conversion does not alter the input image.
- `preview_upload`: Pillow-only thumbnail for viewing before Analyze; applies
  EXIF orientation, composites alpha on white, returns RGB. It is not a second
  processing loader: original bytes still go unchanged to the real loader.
- `processing_controls`: builds all nine public options. Odd denoise kernels and
  adaptive blocks prevent invalid choices. Defaults follow contract v1: median
  3, CLAHE, Otsu, global 127, adaptive block 31/C 11, morphology none/kernel 2.
- `show_results`: displays records, separate arrays, both OCR outputs and
  resolved parameters, then uses `json.dumps` / `render_report` for in-memory
  JSON/Markdown downloads. No upload/report file is automatically saved.
- `main`: loads the local configuration using an absolute path relative to the
  script, validates it, renders controls/previews, invalidates session results,
  handles Analyze and displays only the current result.

The OCR source radio applies to this batch. Its default is processed; original
can recover from processing that damages text. Changing it clears results and
requires Analyze. Classification and field extraction both use that selected
text, with no automatic fallback or attempt to join fields across files.

## DIP control intuition

Median chooses the middle neighbourhood value: [10, 11, 250] becomes 11, reducing
an isolated bright speck. Gaussian uses weighted neighbours and can smooth text
edges. CLAHE enhances local contrast; equalization uses the global histogram.
Global threshold compares with one chosen number; Otsu chooses a global cutoff
from the histogram; adaptive uses local blocks and a constant C. Erosion,
dilation, opening and closing change foreground shapes; the real pipeline owns
text polarity restoration. Select alternatives and inspect their effects rather
than enabling everything. No option is claimed to improve every document.

The six stage names remain `original`, `grayscale`, `denoised`, `enhanced`,
`thresholded`, `morphology`, including copies for bypassed operations. This UI
shows the chosen sequence, not seven final experiment comparisons. Those remain
Sakshi's work and the later evidence gates.
