# SG05 — understand the final experiment

This sprint measures the real M01 application and compares DIP alternatives.
The final results and every measured denominator live in `docs/validation/sakshi.md`
and `outputs/experiments/SG05/`. No report/slides or next sprint is implemented.

## What we measure, and why

Pixels are numbers; OCR tries to turn their shapes into letters. Classification
then looks for supported title phrases and extraction looks for labeled fields.
Readiness checks the configured types/fields. A failure at one step can affect
later steps, so measure text, type, fields and readiness separately.

For example, `Application ID` becoming `Application 1D` changes one character.
The classifier may still recognize Caste Certificate, while the extractor cannot
match the damaged field label. Readiness can still be Ready because application
ID is optional in this demonstration checklist. Readiness is not text accuracy.

## The seven DIP/OCR comparisons

1. **Original/grayscale:** grayscale mixes BGR channels approximately as
   `0.114 B + 0.587 G + 0.299 R`. It removes color while preserving intensity
   information. OCR sees the same page geometry, with fewer channels.
2. **Original/equalization/CLAHE:** a histogram counts pixels at each intensity.
   Equalization redistributes the whole histogram. CLAHE works on local tiles,
   clips large histogram counts (clip limit 2.0 here) and blends tiles (8×8 grid).
   Contrast stddev measures pixel spread, not recognition. A noisier page may
   have higher stddev and much worse OCR, as the final noisy-caste result shows.
3. **Gaussian/median:** a 3×3 Gaussian averages a weighted neighborhood (automatic
   sigma), smoothing noise and edges. Median picks the middle sorted value;
   `[10,10,10,10,10,10,10,10,255]` has median 10, so an isolated bright outlier is
   removed. Either method can erase fine detail; the dataset decides its effect.
4. **Thresholds:** global 127 maps values above 127 to white and the rest black.
   Faint text and background are both above 127, so this page disappears. Otsu
   chooses a cutoff that reduces within-group intensity variance. Adaptive
   Gaussian compares each pixel with its local weighted mean minus 11 (31×31
   neighborhood); local noise can become false black foreground.
5. **Erosion/dilation:** invert dark text to white foreground deliberately. With
   a rectangular 2×2 neighborhood, erosion keeps only foreground that survives
   the minimum operation; it thins characters. Dilation uses the maximum,
   expanding characters. Restore polarity for OCR. The even 2×2 kernel uses
   anchor (1,1), so it may also shift boundaries directionally.
6. **Opening/closing:** opening is erosion then dilation; closing is dilation
   then erosion. They respectively remove small foreground islands and fill
   small foreground gaps. They are independent demonstrations on Otsu text,
   not an instruction to chain all operations.
7. **Original/default OCR:** fixed median3 → CLAHE2.0/8×8 → Otsu → no morphology.
   Tesseract uses English and page segmentation mode 6 (one text block), with
   20-second timeout. Original OCR remains available when a method hurts.

## CER, field scoring and honest failures

Levenshtein distance counts minimum unit-cost edits. `cat` → `cut` has one
substitution and CER 1/3. `a` → `abcd` has three insertions and CER 3: CER is not
limited to 1. A nonempty reference versus empty OCR has CER 1; no reference is
undefined and rejected. Engine errors have null CER, saved diagnostics and a
nonzero runner exit. They are not empty successful recognitions.

Comparison copies are casefolded and whitespace-collapsed; punctuation remains.
Raw OCR and reference strings stay separate. Normalization can conceal a lost
line boundary: CER may be zero while the label-based extractor fails. Exact
field scoring uses unmodified string values and counts absent slots separately.
Pooled CER uses total edits / total reference characters; mean CER averages the
eight page scores. Related derivatives do not supply eight independent layouts.

`ok` only means OCR returned alphanumeric text. On the noisy equalized page it
returned long garbage and still passed the length-based readable heuristic.
Unknown classification keeps it from satisfying a checklist type. A clean
sample of the same type can satisfy that type in the eight-image submission;
inspect per-file results so duplicates do not hide a damaged method.

## Key functions in scripts/evaluate_dataset.py

- `final_methods(image)` reuses the verified SG02/SG03 numerical functions to
  construct 14 fixed alternatives. Parameters are recorded and input arrays
  stay unchanged. No reference text chooses a production setting.
- `evaluate_observation(sample, reference, result)` compares actual OCR against
  expected type/fields and computes CER. Reference-only rules and expected-type
  extraction are explicitly separate diagnostics, never substitutes for OCR.
- `summarize(rows)` retains real denominators. It excludes engine errors from
  CER but includes them in attempted type/field counts; no_text is scored.
- `record_for_method(...)` creates development evaluation records with the real
  original OCR plus the selected alternative. The app path runs independently.
- `run_evaluation(...)` verifies reviewed data hashes, saves image/text/figure
  evidence, invokes the unchanged production byte-upload orchestrator, computes
  readiness and saves tables plus source/artifact fingerprints. It rejects a
  nonempty output directory rather than mixing old and new evidence.
- `save_ocr_pair(...)` shows two fixed pages without extra empty panels. Other
  figures use identical intensity ranges and the same page inputs.

## How to run and inspect

Use the exact commands in `docs/validation/sakshi.md` from Sakshi's checkout.
The local venv and Tesseract were verified; no package installation was needed.
The default evidence directory already contains the verified result, so choose
a new empty `--output-dir` for another run. Expect 112 method progress lines,
then 8 production records (16 more real calls); measurements are saved even if
an engine error causes a failing exit. The reproduction command runs every
recognition again; the test audit recomputes arrays/metrics/rules from stored
text and should not be described as 112 fresh OCR calls.

For suspected failures inspect each row's OCR status/error, then the saved raw
text, classification evidence, expected/observed fields, reference-only rule
diagnostic and expected-type field diagnostic. The final table contains seven
nonzero-CER rows and five type/field-mismatch rows. No peer-owned bug was
established; no transcript-driven repair, settings change or claimed improvement.

Final full-suite/reproducibility results and exact reviewed figures are in the
validation summary and handoff. SG05 is prepared for M02; only M02 freezes the
combined SG05/JB05 evidence. SG06 waits for that gate.
