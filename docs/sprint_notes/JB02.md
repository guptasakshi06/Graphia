## What we built and why

`modules/extraction.py` implements `extract_fields(text, doc_type)` using only
Python's `re` and `datetime.date`. This is the application step after OCR;
it adds no DIP operation. A label tells us what a nearby value means:
`Certificate Number: INC-00017` can supply a certificate number, while
`Annual Income: 48000` cannot. We never guess fields from arbitrary numbers.

A regex capture group saves a selected portion of a match. `(?P<label>...)`
saves the label and `(?P<value>...)` saves the value. `fullmatch()` checks the
whole line, avoiding matches hidden in a label like `Old Student Name:`.
`[ \t]+` permits spaces/tabs within labels without crossing newlines. The
colon separates label and value. Blank labels cannot consume the next line.

## Key functions and output

`extract_fields()` validates the caller's text/type, starts all four fields at
None, collects labeled candidates line by line, and accepts only a single
consistent valid value per field. Matching ignores label case, but preserves
value case and leading zeroes. Whitespace within names is collapsed. The
original OCR string remains unchanged and must be retained by the caller.

`_validate_value()` checks one candidate's format. It returns the original or
whitespace-normalized value on success, otherwise None. `date.fromisoformat()`
checks whether the ISO date actually exists, including leap years. There is
no `O` to `0` correction, truncated-ID salvage, date guessing or name fallback.

## Supported demonstration layouts

| Field | Labels (case insensitive) | Accepted values / applicability |
|---|---|---|
| `student_name` | `Student Name:` | English ASCII letters, spaces, initials with periods, straight apostrophes and hyphens; 2–80 characters; all four known types |
| `certificate_number` | `Certificate Number:`, `Certificate No:`, `Certificate No.:` | Numeric-only string or `INC-` / `CST-` followed by numeric groups; respective income/caste type only |
| `application_id` | `Application ID:` | Numeric-only string or `APP-` followed by numeric groups; all four known types |
| `issue_date` | `Issue Date:` | Exact `YYYY-MM-DD` and valid calendar date; all four known types |

IDs are limited to 64 characters, use ASCII digits and may have multiple
hyphen-separated numeric groups after their prefix, such as `INC-2026-0042`.
Prefix case is ignored for validation and retained in the returned string.
Numeric-only IDs preserve zeroes: `000041` stays a string. Different prefixes,
spaces within IDs, extra prose/punctuation, and damaged digits are rejected.
These formats are demonstration choices, not rules for official documents.

Each field needs its own line with a colon and same-line value. Leading/trailing
spaces/tabs and CRLF/CR/LF line endings are supported. `Certificate No[.]` is a
small explicitly authored fixture extension; the four canonical labels also
match Sakshi's existing sample generator/references, inspected read-only.
Unknown documents return four None values even if labels appear. Marksheet
and identity proof always return None for certificate number.

Repeated identical valid values are accepted. Conflicting values, or a valid
value alongside an empty/malformed occurrence of that supported label, leave
that field None. A bad field does not discard independent valid fields.
Placeholder text such as `Not Found`, `Unknown` and `Unreadable` is missing.
Non-string text/type raises TypeError; an unsupported type ID raises ValueError
so caller mistakes are visible. Callers should pass the classifier's type ID.

## Limits and JB03 recommendation

Only these labeled layouts are supported. Wrapped values, multiple fields on
one line, non-ASCII names, unsupported synonyms/dates/identifier formats and
missing colons may stay missing. Well-formed but incorrect OCR text can pass
format checks; regex cannot verify the identity or correctness of a name/ID.
Conflicting names are not resolved automatically. Contract v1 has no separate
reason metadata: absent, malformed, conflicting and not-applicable values all
use None. The later UI/report should display `Not Found / Unreadable` as
appropriate, without replacing stored None with an invented value.

Keep contract-v1 readiness recommendations: require `student_name` on the four
known types, and `certificate_number` additionally on income/caste certificates.
`application_id` and `issue_date` remain optional initially. Extraction does not
judge readiness, official eligibility, authenticity, or whether uploads belong
to the same student. No configuration or readiness module is implemented here.
