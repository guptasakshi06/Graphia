## What we implemented and why

DIP prepares pixels. OCR recognizes characters in those pixels. Pytesseract is a
Python wrapper: the actual recognition runs in the system Tesseract executable,
using installed language data such as `eng.traineddata`. Installing Pytesseract
alone does not install that executable/data. All work runs locally.

Page segmentation tells the engine what layout to expect. Here `psm=6` assumes
one uniform text block. It fits our simple single-column classroom pages. It is
not a reliable universal layout assumption for forms, multi-column pages or photos.
Mode 3 provides automatic page segmentation; mode 7 expects a single text line.
The wrapper accepts text modes 1 and 3–13; it rejects mode 0 (orientation-only)
and mode 2 (unimplemented), since they cannot satisfy this text API.

Before OCR, OpenCV BGR arrays must become RGB; otherwise red and blue are swapped
when Pytesseract interprets the array. Gray arrays remain gray. Both routes use a
fresh array, leaving the caller's original pixels unchanged. Image loading,
EXIF/alpha handling and the 1800-pixel limit remain SG01's responsibility.

## Key functions and result handling

- `modules.ocr.extract_text(image, lang="eng", psm=6, timeout=20)` calls
  `pytesseract.image_to_string` once with the given language, segmentation mode
  and finite positive timeout in seconds. It preserves raw text, including blank
  lines; it does not read references or infer field values.
- The exact returned keys are `text`, `status`, `confidence`, `error`,
  `engine_config`. `ok` requires at least one alphanumeric character.
  `no_text` means the engine ran successfully but returned blank/punctuation-only
  output. A no-text result retains raw output and has `error=None`.
- Missing executable/data, engine failures, runtime/timeout and file I/O errors
  give `status="error"`, an explanatory `error`, and empty text. The actual engine
  message is retained for language-data failures. Invalid arrays/settings raise
  `ValueError`, consistent with the existing DIP helpers; these are caller errors.
- `confidence=None` is deliberate: the one text call does not measure confidence.
  No confidence aggregation or accuracy percentage is claimed.
- `compare_sg04` defines four fixed methods before reading any results:
  original BGR, grayscale only, contract-default pipeline and grayscale→Otsu.
  Each candidate is derived from the same source; alternatives are not chained.
- `verified_ocr_samples` requires source/reference SHA256 values to match both
  the manifest and SG01's recorded visual review. It refuses unverified/changed
  references and empty normalized references. This revalidates an existing
  assistant inspection; it is not a new human review.
- `run_sg04_experiments` saves actual raw texts, 24 processed input PNGs,
  settings, engine versions, source/output/reference hashes, normalized copies,
  edit counts and CSV/JSON. Error rows have null CER/edit count; the runner saves
  diagnostics then fails (CLI exit 1), rather than scoring engine failure as a
  successful empty recognition. A failed version probe cannot discard OCR errors.

## CER, with numerical examples

Character Error Rate = minimum unit-cost insertions + deletions + substitutions,
divided by the number of normalized reference characters. The dynamic-programming
Levenshtein helper keeps the previous/current row, using memory proportional to
the shorter string. It compares Unicode code points, not grapheme clusters.

Normalization is **Unicode casefold → collapse all whitespace runs to one ASCII
space → trim**. Punctuation and digits remain. No spelling correction, field
replacement, reference-driven output selection, Unicode compatibility expansion
or OCR repair is applied. Normalization copies are saved separately from raw OCR.
Thus case and spacing errors are outside this metric's scope.

Examples: `abc`→`abxc` is one insertion; `abc`→`ac` one deletion;
`abc`→`axc` one substitution: CER is 1/3 in each case. `kitten`→`sitting`
needs 3 edits, CER 3/6. `a`→`abcd` has CER 3/1 = 3, so CER can exceed 1
and is never clipped. Empty hypothesis/nonempty reference has CER 1. An empty
normalized reference is undefined and raises `ValueError`, including empty/empty.

## Actual preliminary results

Tesseract 5.3.4, Pytesseract 0.3.13, OpenCV 5.0.0, NumPy 2.5.4.
`lang="eng"`, `psm=6`, `timeout=20` for every dataset call. All source images
remain 1400×1000 at maximum dimension 1800. Four clear originals and four related
derivatives cover low contrast, seeded noise and mild blur. References include
synthetic banners and disclaimers as well as titles, labels and field values.

All **32/32** real calls returned `ok`; no setup/no-text errors occurred in the
dataset run. Each method has 0 edits / **2190** reference characters, mean CER 0
and pooled CER 0. Those 2190 characters are shared across methods, and derivatives
repeat their parent's text. They are not independent unseen documents. The metric
ignores case/spacing differences. This is a small easy synthetic demo set, not
proof of general OCR accuracy, authenticity, official eligibility or readiness.
No measured OCR improvement or winner exists among these candidates.

Raw outputs inspected as text: clear-income original and blurred-marksheet default
(the title, name, identifiers, dates and disclaimer were present). Every saved
result and its recomputed metric/image/hash is audited by tests; that does not
claim a new visual inspection of every page or a human walkthrough.

## Default selection for M01

Retain the frozen contract-v1 default: **median 3×3 → CLAHE clip 2.0 / 8×8 tiles
→ Otsu → morphology bypass**, processed OCR selected by default. All four methods
tied on this sample set; there is no evidence here to justify a public-default
change. This choice preserves the agreed interface, not a claim of optimality.
Grayscale+Otsu explicitly overrides `denoise="none", contrast="none"` and keeps
other resolved settings. SG03 already shows global 127 erasing faint text and
morphology damaging thin strokes, so those demonstrations are not blindly chained.

Keep original/grayscale options available when preprocessing damages an unfamiliar
upload. At M01 the real UI must retain both OCR results and allow manual source
selection with recalculation of type/fields. Production never sees transcripts or
chooses the lowest-CER method per uploaded document. There is no automatic
reference-based selection in `extract_text` or `run_pipeline`.
